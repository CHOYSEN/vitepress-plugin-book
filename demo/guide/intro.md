# 阅读进度追踪

## 插件如何记住你的阅读进度？

每次你打开一个页面，插件会将这个页面路径记录到浏览器的 `localStorage` 中。
关闭网站后再次打开，插件会对比你当前访问的页面和上次离开时的页面是否一致。

如果不一致，它会在页面顶部弹出一个提示：

> 📖 继续阅读上次的章节？ [继续] [✕]

点击「继续」会自动跳转到上次阅读的章节；点击 ✕ 关闭提示继续浏览当前页面；
如果不操作，提示会按照你设定的 `toastDuration` 秒数后自动消失。

## 滚动位置记忆

这个功能会记住你在每个页面的滚动位置。试试看：

1. 滚动这个页面到中间某个位置
2. 点击侧边栏导航到「自定义配置」页面
3. 再从侧边栏回到这个页面

你应该会回到刚才滚动到的位置，而不是从页首开始。这意味着你在长篇文档中反复查阅时，不需要重新寻找上次读到的地方。

不过有一个例外：如果 URL 里有 `#` 锚点（比如你点击了某个标题链接），插件会跳过滚动恢复，让浏览器正常定位到锚点位置。

## 一大段文字，用于测试回到顶部按钮

程序员每天都要阅读大量的文档。一个好的阅读体验不仅能提高效率，还能减少疲劳感。

阅读技术文档时，我们经常需要在不同的章节之间跳转。有时候刚读了半页，需要切到另一个页面查个 API 的用法，
再切回来就忘了刚才看到哪里了。这个场景非常常见，尤其是在学习新技术的时候。

纸质书有书签，Kindle 有同步功能，但用 VitePress 部署的开源书籍网站往往只能靠浏览器的书签或历史记录。
这个插件试图弥补这个差距，把电子书阅读器的核心体验带到技术文档网站上。

VitePress 本身已经是一个优秀的文档框架——静态生成、Vue 驱动、主题美观。
但它缺少读者视角的功能。读者希望知道哪些章节读过了、读到哪里了、总共还有多少没读。
这些是 Reader 插件要解决的问题。

## 再来一段长内容，确认滚动条够长

阅读开源书籍时，一个典型的问题是内容的非线性浏览。你不是从头读到尾，
而是先看目录，找到感兴趣的部分，跳过去读一段，再回到前面看基础概念。这种阅读模式下，
「最近读到哪了」这个问题比线性阅读更复杂。

Reader 插件采取的方案是：记住每页的滚动位置，而不是只记住章节。
这样不管你在哪一页、滚到了什么位置，下次回来都能准确恢复。

还有一个细节值得注意：自动跳转的体验。如果插件在你每次打开网站时都静默跳转到上次的页面，
可能会让用户困惑——"我明明点了首页链接，怎么跳到了别的地方？"
所以默认行为是弹出一个 Toast 提示，让用户选择是否继续阅读。

这个细节虽然很小，但体现了对用户体验的考虑。做工具类插件和做产品类网站不同，
工具应该安静地在背后工作，只在必要的时候介入用户的流程。
